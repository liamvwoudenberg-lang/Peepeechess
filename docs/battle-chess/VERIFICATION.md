# Battle Chess release verification — 1.3

- TypeScript validation, the production web build, and all **69 Node tests** passed. New tests cover both capture outcomes, legality and king-safety restrictions, en passant, every promotion, castling rights, move counters, checkmate/stalemate, repetition, fifty-move/material/agreed draws, role stats, active hit frames, one-hit limits, range/facing (including repeated full orbits), stamina, guard breaks, timed parries, dodge recovery, all six abilities, timeout ties, host pause and one-time settlement. A pawn defeats a queen through timed parries and counters in the combat test.
- Real WebSocket authority tests create two seats, reject opponent moves, fabricated victories and invalid credentials, run combat from actual input commands, verify the resulting boards, reconnect the same seat and enforce disconnect forfeits. A client test checks that rejected room admission displays the real error instead of retrying indefinitely.
- The production browser completed the entire shared-device loop: select Battle Chess, start, play `e4 d5 exd5`, enter a real WebGL arena, control both fighters with separate keyboard inputs, block and attack, win by knockout, apply the attacker victory, and continue chess. The arena unmounted on return and the dedicated results panel handled resignation. A saved active Classic game also survived opening a Battle room link. See `browser-checks.json`.
- Two independent production-browser clients created/joined a private room, each controlled its own third-person fighter, Black won the defender duel **by knockout**, both boards removed the attacker and retained the defender, and the next authoritative chess move synchronized. No client-set winner, scripted hit outcome or random winner was used. This used the real local Node/WebSocket server, not a simulated online UI.
- Offline phone checks loaded the actual arena from the service-worker cache, used two simultaneous touch joysticks and simultaneous attack/dodge touches, recorded real stamina costs, checked portrait/landscape bounds and 44px action targets, saved an unfinished duel and resumed it after reload. They also removed `structuredClone`, denied the Gamepad API and applied **6× CPU throttling**; keyboard/touch play remained available. This is browser emulation, not physical-device performance certification. See `mobile-checks.json`.
- The illustrated board, shared-device arena, two faction/class figures, over-shoulder cameras and phone controls were visually inspected. The Elven Rook / Skeleton Queen image uses a valid custom-position capture checkpoint and the real resumable game component. It is a visual check, not a claim that the position was reached from the standard opening.
- Classic browser regression checks passed for friends, persistent chat, private challenges, spectating, emotes, reconnect, disabled online coaching, computer replies, profile editing, drag movement, analysis import, all promotion choices, underpromotion and multi-move puzzles. Responsive Classic screens remained within their viewports. See the two `classic-*-checks.json` files. One early run overlapped a web rebuild; recorded successful results came from a finished build.
- Android **1.3 (code 5)** assembled successfully. Its v1/v2 debug signatures and Android SDK metadata were verified; every bundled web file matches the final `dist`. The Battle UI, arena chunks, character code and offline cache are bundled, test fixtures are excluded, and signing compatibility with 1.2.1 is recorded in `apk-verification.json`.

Private room verification used one local Node process. Vercel Functions do not host the persistent combat server. Local two-player Battle Chess works on the static site/APK, while real private rooms require the included Node/WebSocket host. Rooms are in memory, unrated and independent of Classic profile ratings. No public deployment, physical Android/iPhone/gamepad test, Internet latency benchmark, production load test or tournament-balance claim is made.

Kings use checkmate and do not enter capture duels. The King fighter is defined and tested in the common combat system, but this ruleset does not expose a capturable-king mode. Battle bots, ranked Battle queues, durable hosted rooms and Internet prediction/interpolation remain future work. Full rules, controls, file map and hosting instructions are in [BATTLE-CHESS.md](../../BATTLE-CHESS.md).
